# OpenSolve Pipe — Claude context guide

Free, browser-based steady-state hydraulic analysis of pressurized pipe networks: no install, shareable by URL, desktop and mobile equal. `apps/api` (FastAPI, our own GGA network solver, the reference suite) and `apps/web` (SvelteKit). v1 (D5) is built and deployed by the owner; it is **not a stable release** (D14). Calculation methods are at `METHOD_VERSION` 1.6.0 (`services/solver/version.py`).

This file is loaded into every session, so it holds only what every change needs: the reading map, the binding rules and the decision index. Details live one link away. Keep it under 16 KB; `apps/api/tests/unit/test_docs.py` fails when it grows past that or a link breaks.

## Rules that bind every change

The decision in brackets holds the details and the reasoning.

- **Correctness over everything** (GOALS §3). Never weaken a test to make it pass: no loosened tolerance, skipped test or deleted assertion. Fix the cause, or leave the feature out and say so.
- **No uncited numbers** [D8]. Every coefficient, correlation, property and expected test value comes from a library function you call and cite, a closed-form derivation written out in the test, or an EPANET run. Never type a textbook or Crane value from memory. Never use `fluids`' fuzzy free-text roughness lookup. Hydraulic data lives in versioned JSON under `apps/api/src/opensolve_pipe/data/`, with a citation per entry, generated by a script where a library has the data.
- **The reference suite proves correctness** [D6]. Any change to solver or loss-coefficient code keeps `apps/api/tests/reference/` green (0.5 % or 0.01 m of head, whichever is looser). A new component type ships with at least one reference case, written by someone who did not read `services/`; expected values are never computed with solver code.
- **Same answer, different answer** [D13]. Results that agree within D6 are the same answer. Zero-flow labels, iteration paths and convergence-level noise are not regressions and are never taken to the owner. A solver change is accepted by the suite, the corpus comparison and the three fuzz profiles, with the criteria in D13.
- **Method version** (GOALS §4.3). Any change that can alter a solved value bumps `METHOD_VERSION` and adds a `METHOD_CHANGELOG` entry (never remove one), proven by the corpus comparison (TSD §10.4). A feature that adds results without changing any existing value leaves the version alone.
- **Traceability is part of done** [D10]. Every solved element carries a trace (inputs with sources, equations, correlations, cited data, the inequality that set its state); every solve has a methods summary; a value equal to a field's default is labelled "default".
- **SI inside, gauge at the edges** [D4]. The model, API and solver are SI only; users see gauge pressures; unit conversion happens only in the web app.
- **Privacy** [D3, D10]. No analytics, cookies or third-party requests. Project data travels only in the URL fragment and in request bodies, and is never logged; `VALIDATION_ERROR` never echoes a submitted value.
- **Results first, physics flagged** (GOALS §4.6). Always solve; flag physically invalid results by default; design-practice checks are opt-in [D19].
- **Nothing is released yet** [D14]. `schemaVersion` stays 1; no migrations or compatibility shims until the owner declares a stable release; the schema-v1 fixture link is regenerated when the model changes.
- **Pydantic models are the API's source of truth.** Frontend types are generated (`pnpm gen:types`); rules JSON Schema cannot express are published as `x-…` OpenAPI extensions and read by the web app, never copied [D10]. Generated files are never edited by hand: `apps/web/src/lib/api/{openapi.json,schema.d.ts}`, `data/pipe_materials.json`, `data/api526_orifices.json`, the reference case JSONs.
- **Topology.** Every network needs a fixed-pressure boundary (reservoir or reference node); assigned flows never count as one [D1, D12]. Topology problems are 422 with every issue listed; validation and fluid-range errors 400; one error envelope [D10].
- **Branches.** Web-only changes go on a `web/<topic>` branch (Cloudflare Pages previews it at `https://web-<topic>.opensolve-pipe.pages.dev` against the deployed API); a change that touches the API goes elsewhere. Develop on the branch the session assigns, never force-push, open a PR only when asked.
- **AI-written code meets the same bar** (GOALS §7.2): the reference suite, not review, establishes hydraulic correctness.

```
                                                tests/{unit,reference,differential,fixtures}   scripts/
apps/web/   SvelteKit 2 / Svelte 5 (pnpm)       src/lib/{api,components,state,utils,testing}   tests/ (Playwright)
docs/       GOALS, PRD, SDD, TSD, decisions/, proposals/, prompts/, workflow, history, roadmap
```

TSD §3.1 has the file-level tree. Add directories when the code that needs them lands; never scaffold empty ones.

## Tooling

```bash
# backend (apps/api)
uv sync
uv run uvicorn opensolve_pipe.main:app --reload --port 8000     # /openapi.json always; /docs only with API_DOCS=1
uv run pytest && uv run ruff check . && uv run ruff format --check . && uv run mypy src
uv run python scripts/generate_pipe_data.py --check && uv run python scripts/generate_relief_data.py --check

# frontend (apps/web)
pnpm install && pnpm dev                                         # http://localhost:5173
pnpm gen:types && git diff --exit-code -- src/lib/api            # generated API types up to date
pnpm check && pnpm lint && pnpm test && pnpm test:e2e            # e2e starts its own API (8010) and app (4183)
```

Python quality: ruff (lint + format, line length 100), mypy strict on `opensolve_pipe`, pytest. Frontend: ESLint, Prettier, `svelte-check`, Vitest, Playwright 1.56.1 pinned (never run `playwright install` where browsers are preinstalled). No other infrastructure in v1; Docker only for the API's Cloud Run image. The full gate list and the corpus proofs: [`docs/workflow.md`](docs/workflow.md) §4.

## Conventions

- Write code that reads like the surrounding code. Comments and docstrings cite the decision or spec section they implement (`CLAUDE.md D22`, `TSD §10.4`).
- Results-first UI; every view works on phones (GOALS §4.7). Web defaults recorded in decisions are the designers' and reversible under D14.
- Keep it simple: the v1 scope (D5) before anything deferred; one verified slice at a time (GOALS §6).
