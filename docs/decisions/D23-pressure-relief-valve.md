### Model

`ReliefValve`, type `relief_valve`, ports `inlet` → `outlet`: a conventional spring-loaded pressure relief valve in liquid service, its own type, not a `valveType`. A required `setPressure` Δp_s (Pa, a difference, (0, 10⁸], no default): the static pressure difference, inlet minus outlet, at which it starts to open. Discharging to atmosphere at the valve's elevation it is the gauge set pressure; against a constant back pressure it is the bench setting (owner: a difference, as a conventional valve's spring sees it; balanced-bellows and pilot valves, set on the inlet's gauge pressure, are Later). A required `capacity`, a union on `kind`, three kinds never mixed (owner; "never an effective coefficient or area with a rated coefficient or actual area", Pentair TP-V300 ch. 5): `api526` `{letter}` (D to T, API 526's effective area) or `effective` `{area}` (an API 520 effective area, m², (0, 78.54]), each with API 520's effective coefficient Kd = 0.65 and ASME's overpressure, fixed and labelled preliminary; or `certified` `{area, dischargeCoefficient, overpressure?}`, the valve's actual area and rated coefficient ((0, 1], ASME's K = 0.9 × the measured coefficient) from its certification, and its full-lift overpressure ((0, 1]). An unknown kind is 400 `invalid_capacity`, never quoting it. `status` is `active` (the default) or `locked_closed` (gagged, or isolated by its block valve); failed open is Later. API 526's letters and areas, Kd 0.65, and ASME's fraction, floor and scope live in `data/api526_orifices.json`, which `scripts/generate_relief_data.py` writes from fluids 1.3.1 with a citation per entry and a `--check` mode (D8's pattern), published as `x-relief-data` on the ReliefValve schema. Each value's only model rule bounds it; `schemaVersion` stays 1 (an additive type, D14). *(GOALS §4.1: no source gives a default set or capacity.)*

### Overpressure

op, the rise of the difference above the set at which the valve reaches full lift, as a fraction of the set. The default is ASME VIII's liquid certification overpressure, max(10 %, 3 psi/Δp_s) (Pentair p. 3.15), labelled "default" (D10), for a set of at least 15 psi (103,421.36 Pa, ASME VIII's scope, Pentair p. 5.3), where it lies in [0.1, 0.2]. A letter or an effective area always takes it; a certified capacity may give its own (owner). It is not the allowable accumulation a valve is sized for.

### Law

On Δp_t = ρg(h − (z_in − z_out)), h = EGL_in − EGL_out, the total-pressure difference between the ports (D7): the lift x = clip((Δp_t − Δp_s)/(op·Δp_s), 0, 1) and Q = x·Kd·A·√(2Δp_t/ρ), API 520's liquid equation at lift x in exact SI (fluids `API520_A_l`'s raw form, Kw = Kc = Kv = 1; API's rounded constant 11.78 gives 6.092144×10⁻⁵ more area, which the trace states) (`services/solver/relief.py`). Inverted for the GGA: h(Q) = h_set + (Δp(Q) − Δp_s)/(ρg), h_set = Δp_s/(ρg) + z_in − z_out. In the band u = √Δp is the largest real root of u³ − Δp_s·u − RQ = 0, R = op·Δp_s/(Kd·A·√(2/ρ)) (the trigonometric form while 27(RQ)² ≤ 4Δp_s³, which holds over the whole band for op ≤ 1/3, Cardano's otherwise), with Δp − Δp_s = RQ/u and dΔp/dQ = 2uR/(2Δp_s + 3RQ/u), both without cancellation. From Q_f = Kd·A·√(2Δp_s(1 + op)/ρ) on, Δp = ρQ²/(2(Kd·A)²). h is continuous at Q_f (its slope steps up there) and strictly increasing, with a finite positive slope R/(√Δp_s·ρg) at zero flow; for Q < 0 Newton sees the odd extension about h_set and the status rule closes the valve, so no reverse law is used. The valve is a `LinkKind.VALVE` link in `built.valves`; `gga.py` and `system_curve.py` are unchanged. *(GOALS §4.1: exact at the two certified points, and checkable by hand.)*
- **Three named departures,** each stated in the methods summary and every trace:
  - **The band between set and full lift is a convention, not the cited behaviour.** API 520 and ASME certify one point, the capacity at set plus overpressure. The linear lift is MathWorks Simscape's and AFT Impulse's convention, exact at the two certified points. Pentair's typical liquid-trim characteristic (TP-V300 Fig. 4-12, p. 4.8) lifts to about half at 107 % of set, surges to full lift there and recloses near 90 %, so a real valve has two steady states between about 90 % and 107 % of set. Measured with the real solver: the figure's rising branch (with a chord across the surge) puts the inlet 0.31–0.88 % of set higher with 1.4–19.4 % less flow; a valve that has surged open sits 3.4–12.0 % of set lower with 19–85 % more flow (D13: another state, not searched for). No cited source verifies any band law, so **the owner accepted the band as an exception to GOALS §5's Verifiable gate and to §4.1 (2026-10-28)**: every relieving state short of full lift is flagged, and the band's reference cases verify the implementation of the convention, not the convention.
  - **API 520's P1 − P2 is read as Δp_t.** ASME's definitions as Pentair quotes them (inlet stagnation, outlet static) differ by the outlet velocity head: up to 4.60 % of the difference at full lift for an API 526 T orifice on an 8 × 10 Sch 40 body (test inputs). Δp_t keeps h(Q) increasing for every pipe size (the band's least slope ratio is op/(2 + 3op)), where the literal reading does not, and gives the higher inlet pressure at a given flow. The trace shows both other readings, marked not used.
  - **With a superimposed back pressure the overpressure is taken on the set difference,** as the opening is (an inference for full lift, named). Full lift then comes op × the back pressure below the in-situ relieving pressure (C6: 383.04 against 385.00 kPa(g)); at the relieving pressure both readings are at or past full lift and give API 520's flow and the same size.

### Status and the closed start

The check valve's rule (EPANET 2.2 cvstatus) with the cracking head h_set, through `ControlKind` `"relief"`, which takes the check branch wherever a rule is applied or a closed element is bounded (the status update, a disconnected section's openings, the closed-off constraint H_in − H_out ≤ h_set + Htol, the free-level test), with its `RULES` and `KIND_NAMES` entries; no new tolerance. At zero flow h − h_set = (p_in − p_out − Δp_s)/(ρg) exactly, so the valve opens once the static difference exceeds the set by ρg·Htol. A check valve's cracking pressure, unlike the set, is compared with the EGL difference; moving it is Later, with its D13 corpus cost. A solve starts an active relief valve closed, its normal state: started open, a pump deadheaded behind a valve set above its shutoff closes with it and the discharge has no pressure (D9's zero-flow multiplicity); started closed, the pump runs at zero flow with its shutoff pressure on the inlet. **As built,** a system-curve point starts an active relief valve open, as a check valve starts: there the pump is a fixed flow, which a closed valve in its only way out left starved with no rule to re-open it (every cold `/system-curve` point above zero flow had no head). H_sys(0) is then h_set plus the static terms, and every point holds the law. `locked_closed` is fixed closed. A loop whose only fixed head is the valve's discharge floats when started closed (`UNDETERMINED_PRESSURE`, the valve with no result). A valve inside a floating section has its flow, lift and differences, and null pressures. The solver reports the state it reaches and does not search for others (D13).

### Flags and refusal

`RELIEF_VALVE_OPEN` (info, new) at full lift, saying "beyond its rated overpressure" past Q_f. `CORRELATION_OUT_OF_RANGE` (warning, `limit: 'partial_lift'`) on every relieving state short of full lift, naming Fig. 4-12. `RELIEF_VALVE_CLOSED` (info, new) on an active valve closed with a closed-off or floating side, which has no result, `details` {side, section ('floating' or 'closed_off'), setHead, setPressure, and, where the other side has a head, pressureLimit: the bound on the missing side's static pressure that keeps the valve closed}, its message naming those levels as the valve's own (the other elements around the section can narrow which are steady states). `BELOW_VAPOR_PRESSURE` (invalid) on the component while it relieves with the outlet's absolute static pressure below p_v (at or below 0 Pa for a fluid without one: the rule ports and plates use), outside a floating section: the jet flashes, so the flow solved is too high. `CORRELATION_OUT_OF_RANGE` (warning, `limit: 'viscosity'`) while it relieves at μ ≥ 0.1 Pa·s, with the Kv API 520 10E would give (not applied). No flag for a closed valve that has a result, for flow beyond full lift, or for chatter. `RELIEF_VALVE_OUT_OF_RANGE` (422, after `ORIFICE_OUT_OF_RANGE`, one per valve, quoting its values, the basis and a remedy): Kd·A, its square, Q_f, R or the band root's scale 2Δp_s√(Δp_s/3) not a finite positive normal double at the case fluid's density (each a value the law uses or divides by); or a set below 15 psi whose overpressure would be ASME's default (a letter, an effective area, or a certified capacity without an overpressure), with the remedy of a certified capacity and its overpressure. No refusal on geometry. *(GOALS §4.6.)*

### Results and traceability

`SolvedState.reliefValveResults`, always present (`{}` without relief valves or when the solve did not converge); no `ValveResult`. Fields: state (`closed`, `partial_lift`, `full_lift`); flow (+ inlet → outlet; a valve open at its switch can report a flow within Qtol below zero, closed); lift (Q/(Kd·A·√(2Δp_t/ρ)), without the forward form's cancellation); headLoss; totalPressureDifference; pressureDrop (static, as a valve's); inletPressure and backPressure (gauge, null in a floating section); setPressure; setRatio Δp_t/Δp_s; overpressure and its source (`asme_default` or `user`); fullLiftPressureDifference; fullLiftFlow; flowRatio; the capacity used, with its area and Kd resolved and, for an effective area, `coveringLetter` (the smallest API 526 letter covering it, fluids `API520_round_size`; null above T); and API's Reynolds number on the orifice. Its trace (element type `relief_valve`): the inputs with their sources (a letter's area and Kd 0.65 `library`, an entered capacity `user`, ASME's overpressure `default`, with its equation and the term, 10 % or the 3 psi floor, that sets it at the set), the law term by term, API's 11.78 form, the full-lift K on the inlet bore (A_in/(Kd·A))² for comparison, the readings not used, the gauge-set overpressure that would put full lift at the in-situ relieving pressure (not used), the Kv not applied, the inequality that set its state (the law's head loss only while it relieves; a valve open at its switch is "open at its switch, reported closed"), and notes on the conventional valve, the three departures, what the certification does not bound (ASME's set tolerance, the rated K's 0.9) and Kw = Kc = Kv = 1. A "Relief valves" methods section after Valves (references API 520, API 526, Pentair, Simscape, AFT, EPANET 2.2 and this decision) and one assumption appear only with a relief valve. *(GOALS §4.2.)*

### Scenarios and goal seek

D15's allow-list gains `status`, `setPressure`, the whole `capacity`, `capacity.letter`, `capacity.area` (an effective or a certified area: `x-override-fields` lists both `holders`), `capacity.dischargeCoefficient` and `capacity.overpressure` (a certified capacity's; null for ASME's default, written "ASME's 10 % or 3 psi (the default)"). Goal seek varies the set (linear), the area (log), the rated coefficient and the overpressure (linear; a certified case on ASME's default starts in the middle of the bounds), never the whole capacity or the letter, and builds the network at each bound of these (D16), its 400s located by index with no id or value. A variable's `baseValue` is null where the base gives the capacity by another kind, and values varied inside a whole capacity that the scenario sets each get that whole capacity holding every value found (D18's rule). Two goals, `relief_valve_flow` and `relief_valve_pressure_drop` (static), which are also Compare's rows; the inlet's pressure is the port goal. Sizing is goal seek on an effective area for the inlet at the relieving pressure, which equals `API520_A_l` at the solved state within its constant's 6.09×10⁻⁵; the Goal seek section names the API 526 letter covering the area found (owner). Relief states enter goal seek's state map (`valve_state`), so a crossing can name a valve opening.
